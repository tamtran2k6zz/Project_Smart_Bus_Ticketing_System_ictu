# SmartBus — kịch bản demo 15 phút, ngày 13/10/2026

## Khởi động trước giờ báo cáo

Mở PowerShell tại thư mục **Project_Smart_Bus_Ticketing_System_ictu**:

```powershell
.\DEMO_START.ps1
```

Nếu Windows chặn script chưa ký, có thể chạy trong một tiến trình riêng:

```powershell
powershell -ExecutionPolicy Bypass -File .\DEMO_START.ps1
```

Đợi dòng **DEMO SẴN SÀNG** và **Đã chuẩn bị 2 vé thanh toán**. Mở http://127.0.0.1:3010. API: http://127.0.0.1:5010/api/health. Hộp thư cục bộ: http://127.0.0.1:5010/demo-outbox.

Lần đầu trên máy khác cần Node.js và cài dependency bằng `npm.cmd ci --prefix backend` và `npm.cmd ci --prefix frontend`. Máy hiện tại đã có dependency. Không cần Supabase, Redis, merchant hoặc SMTP cho bản demo này. Database dùng PostgreSQL nhúng PGlite trong bộ nhớ, tạo từ migration của dự án; không phải dữ liệu production.

**Khởi động lại ngay trước buổi báo cáo**: chuyến để soát vé khởi hành sau 25 phút; hai chuyến dành cho hủy/đổi khởi hành sau 120 và 240 phút. Dừng bằng `.\DEMO_STOP.ps1`, rồi chạy lại `DEMO_START.ps1`. Database demo được tạo mới khi khởi động lại. Đăng xuất rồi đăng nhập lại các tab sau khi reset vì tài khoản có ID mới. Hộp thư chỉ chứa dữ liệu giả; file các lần chạy cũ có thể còn trong `backend/demo-output/outbox`.

## Tài khoản và dữ liệu

Tất cả dùng mật khẩu **SmartBus123!**. Đây chỉ là tài khoản trong demo cô lập.

| Tài khoản | Vai trò / mục đích |
|---|---|
| passenger@smartbus.demo | Tra cứu, đặt vé, QR, theo dõi, vé tháng, phản ánh |
| conductor@smartbus.demo | Phụ xe, được cấp vai trò DRIVER và phân công riêng cho chuyến |
| driver@smartbus.demo | Tài xế: soát vé, gửi vị trí thiết bị, sự cố/trễ |
| manager@smartbus.demo | Điều hành tuyến, trạm, giá, lịch mẫu, tổ lái, duyệt ưu đãi/hủy/đổi |
| finance@smartbus.demo | Báo cáo, xuất file và theo dõi hoàn tiền |
| marketing@smartbus.demo | Voucher; không có quyền xem báo cáo tài chính |
| admin@smartbus.demo | Tạo tài khoản, phân vai trò/khóa, xem nhật ký |

Tuyến **DEMO01: Trung tâm – ICTU – Hồ Núi Cốc**, ba trạm, hai xe 40 chỗ. Mã **DEMO15** giảm 15%. Có hồ sơ sinh viên đang chờ duyệt và 84 chuyến lịch sử giả trong 42 ngày để biểu đồ/dự báo có dữ liệu.

Vé chuẩn bị sẵn: **A01** trên chuyến +120 phút dùng minh họa hủy, **A02** cùng chuyến dùng đổi sang chuyến +240 phút. Hai vé được tạo bằng API đặt chỗ, thanh toán và callback ký hợp lệ. Mã/đường dẫn tại `backend/demo-output/prepared.json`; ID chuyến tại `backend/demo-output/ids.json`.

Để giữ đăng nhập nhiều vai trò, dùng cửa sổ Chrome thường, cửa sổ ẩn danh và Edge; mỗi hồ sơ trình duyệt đăng nhập một vai trò. Các tab trong cùng hồ sơ dùng chung trạng thái đăng nhập, nên không coi các tab đó là phiên độc lập. Có thể đổi vai trò bằng đăng xuất/đăng nhập trong cùng cửa sổ nếu đã tập trước.

## Lời dẫn và câu trả lời khi được hỏi

**Mở đầu:** “SmartBus số hóa hành trình từ tìm chuyến, giữ chỗ, thanh toán và QR tới điều hành, vị trí xe và báo cáo. Hôm nay nhóm trình diễn trên API và PostgreSQL nhúng với dữ liệu giả, nhà cung cấp cục bộ được ghi rõ, không phát sinh thu tiền.”

**Chống bán trùng:** ghế có trạng thái và thời hạn giữ; backend dùng transaction/khóa dòng PostgreSQL, Redis hỗ trợ khi có cấu hình. Giao diện hết giờ không phải cơ chế duy nhất. Bài kiểm thử PGlite cô lập chưa thay thế kiểm thử tải trên PostgreSQL nhiều kết nối thực.

**Thanh toán/QR:** kết quả được xác nhận từ callback kiểm chữ ký, số tiền và merchant; đổi tham số URL không tạo vé. Callback lặp không cấp vé hoặc gia hạn nhiều lần. Thẻ ngân hàng đi qua VNPay. Cổng demo tạo callback có chữ ký bằng khóa demo.

**Hoàn tiền:** từ chối thanh toán chưa thu tiền thì không phát lệnh hoàn; callback thu tiền đến muộn hoặc hủy hợp lệ tạo yêu cầu hoàn. Nhà cung cấp lỗi giữ trạng thái chờ, worker thử lại với mã cố định. Với ZaloPay, tiếp nhận yêu cầu chưa đồng nghĩa đã hoàn xong; phải truy vấn kết quả cuối.

**GPS:** API thông thường không dựng vị trí/ETA khi chưa nhận GPS hoặc dữ liệu cũ. Demo phát vị trí giả qua cùng dịch vụ cập nhật và thông báo; thử thiết bị thật bằng tính năng chia sẻ vị trí của tài xế trong môi trường HTTPS/localhost, tắt mô phỏng trước khi nghiệm thu thiết bị.

**Dự báo:** trung bình ngày cùng thứ (fallback trung bình ngày), hệ số cao điểm do điều hành nhập, số chuyến đề xuất hướng tới 80% sức chứa. Khoảng hiển thị là trung bình ± độ lệch chuẩn nhân hệ số, không phải khoảng tin cậy đã hiệu chỉnh. Lịch sử demo không chứng minh độ chính xác với nhu cầu thật.

## Phạm vi nghiệm thu cần nói rõ

- Chưa nghiệm thu sandbox thật của MoMo/VNPay/ZaloPay vì chưa được cung cấp merchant và callback HTTPS công khai. Không dùng khóa giả cho production.
- Tích hợp hóa đơn là adapter HTTP có idempotency; cần nối hợp đồng API cụ thể, thông tin đơn vị bán và tài khoản nhà cung cấp, rồi nghiệm thu chứng từ gốc. HTML trong demo được đánh dấu DEMO.
- Email demo nằm trong hộp thư cục bộ; email thật cần SMTP đã cấu hình. Camera/GPS mobile và kết nối push cần thử trên thiết bị/mạng thật. Không có app native riêng; frontend web responsive hỗ trợ camera.
- Goal 5 đã có chức năng thống kê/đề xuất/dự báo tham khảo. Muốn nghiệm thu hiệu quả thực cần dữ liệu vận hành thật và tiêu chí sai số được thống nhất.
- Mã nguồn thay đổi ở bản chính cục bộ; chưa tự triển khai lên web app production. Demo này reset dữ liệu khi dừng.

## Kiểm tra lại trước buổi báo cáo

```powershell
npm.cmd run build --prefix backend
npm.cmd test --prefix backend -- --runInBand
npm.cmd run test:postgres --prefix backend
npm.cmd run lint --prefix backend
npm.cmd run build --prefix frontend
npm.cmd test --prefix frontend -- --maxWorkers=1
npm.cmd run lint --prefix frontend
```

Demo API đã bật bằng DEMO_START, chạy thử trình duyệt:

```powershell
Set-Location frontend
$env:PLAYWRIGHT_EXECUTABLE_PATH='C:/Program Files/Google/Chrome/Application/chrome.exe'
npx.cmd playwright test --config playwright.demo.config.ts
```

Kiểm thử trình duyệt làm thay đổi dữ liệu demo; **reset demo sau khi kiểm thử**, trước lúc trình bày. Danh sách chứng cứ và trạng thái cập nhật nằm trong `IMPLEMENTATION_READINESS_2026-10-12.md`.
